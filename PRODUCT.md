# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Single-file static HTML generated by a Python/pandas ETL (`etl/` package, CLI `python -m etl build|approve|release`). Tailwind, Chart.js and DataTables are vendored and inlined at build time; runtime is offline-safe. No framework.

## Users

Internal analysts and project managers on the sales team (Spanish-speaking). Their job: review the quarterly sales report, validate the business logic behind the numbers, and interpret insights before the numbers move up the chain. They are reviewers and interpreters of the data, not data engineers; the heavy lifting is done by the tooling.

## Product Purpose

Automate the quarterly sales reporting cycle: ingest the Excel sales sources, consolidate them, and generate an interactive single-file dashboard that internal stakeholders use to validate and interpret sales performance. Success means a trustworthy, instantly readable dashboard produced in minutes instead of hours of manual spreadsheet work.

## Positioning

A hybrid agentic cell: the agent does the heavy data wrangling and frontend generation, the human owns validation and business interpretation. What neighboring reports cannot truthfully copy: a fully offline, auditable, single-file dashboard whose release is gated by human approval bound to a cryptographic fingerprint of the artifact.

## Operating Context

Local execution on macOS (M1+). Analysts deposit the Excel sources in the working directory and run `python -m etl build|approve|release`. The dashboard is opened in a browser on desktop, tablet, and mobile. Current dataset covers Jan-May 2026 (partial year), labeled explicitly with no YoY claims. Human-in-the-loop: approval is bound to a SHA-256 fingerprint and run_id before release.

## Capabilities and Constraints

- Read-only over source Excels; inputs are never mutated (verified by byte-identical SHA-256 before/after runs)
- Join on `ID Transacción` with a 90% match threshold; below threshold is fail-stop (no output, FAILED audit row, non-zero exit)
- Dtype validation on numeric columns (e.g. `Total (USD)`); ISO date parsing before aggregation
- String sanitization before JS injection
- `data_log.csv` audit trail per run
- Approval gate: `approve` + `release` commands bound to artifact SHA-256 + run_id; `release` recomputes the digest and blocks on mismatch or missing approval
- Runtime offline-safe (vendored assets inlined)
- No inventory/stock module: out of scope, no dataset exists
- Internal audience only; not client-facing

## Brand Commitments

None prior. The user pinned the visual direction for the dashboard: modern, minimalist, Apple-like aesthetic, with no corporate palette constraints. The dashboard is an internal tool.

## Evidence on Hand

- Real Excel datasets: `Usuarios_Ventas_2026.xlsx` (100 rows) and `Ventas_Productos_2026.xlsx` (100 rows)
- Verified aggregates: USD 274,285 total sales, 1,035 units, avg ticket USD 2,742.85, 100 transactions, Jan-May 2026
- Verify report: PASS, 16/16 requirements, 20/20 scenarios, 0 CRITICAL, 0 WARNING
- Existing generated `dashboard.html` (897 KB) is the incumbent to be redesigned; spec requires KPI cards, 6+ Chart.js charts, and a DataTable

## Product Principles

- Trust first: numbers must be verifiable and auditable; never obscure the data
- Clarity over decoration: the dashboard exists for interpretation, so scanability wins
- Offline and portable: one file that works anywhere with no runtime dependencies
- Human-in-the-loop: release requires explicit approval bound to the artifact
- Internal-tool discipline: serve the analyst's real task, not marketing
